# Real AI Model Provider Setup

This backend now supports real model providers in addition to the mock provider.

## Supported providers

```text
AI_PROVIDER=mock          # local fake response, no credentials
AI_PROVIDER=azure-openai  # Azure OpenAI / Foundry OpenAI endpoint
AI_PROVIDER=openai        # OpenAI chat completions
AI_PROVIDER=foundry       # placeholder Foundry agent endpoint adapter
```

For `AI_PROVIDER=azure-openai`, the backend now supports both endpoint styles:

```text
AZURE_OPENAI_API_STYLE=chat-completions  # Azure OpenAI resource root endpoint
AZURE_OPENAI_API_STYLE=responses         # Foundry endpoint ending in /openai/v1/responses
```

If `AZURE_OPENAI_ENDPOINT` already ends with `/openai/v1/responses`, the backend automatically uses the Responses API.

## Recommended production/portfolio path

For a SharePoint enterprise demo, prefer this path:

```text
SPFx Web Part
  -> Azure Function / local function dev server
  -> Azure OpenAI deployment
  -> later: Graph or Azure AI Search grounding
```

Do not place API keys in the SPFx web part. Keep model keys only in Function App settings, local environment variables, or Key Vault.

## Azure OpenAI local settings

Create a real `local.settings.json` from `local.settings.sample.json` and set these values locally. Do not commit the real file.

```json
{
  "IsEncrypted": false,
  "Values": {
    "AzureWebJobsStorage": "UseDevelopmentStorage=true",
    "FUNCTIONS_WORKER_RUNTIME": "node",
    "AI_PROVIDER": "azure-openai",
    "AI_TEMPERATURE": "0.2",
    "AI_MAX_TOKENS": "900",
    "AZURE_OPENAI_ENDPOINT": "https://YOUR-RESOURCE.services.ai.azure.com/openai/v1/responses",
    "AZURE_OPENAI_API_KEY": "[REDACTED]",
    "AZURE_OPENAI_DEPLOYMENT": "nextcore-gpt-5-4-mini",
    "AZURE_OPENAI_API_VERSION": "2024-06-01",
    "AZURE_OPENAI_API_STYLE": "responses"
  }
}
```

For the older Azure OpenAI resource-root + chat-completions style, use this instead:

```json
{
  "AI_PROVIDER": "azure-openai",
  "AZURE_OPENAI_ENDPOINT": "https://YOUR-RESOURCE.openai.azure.com",
  "AZURE_OPENAI_API_KEY": "[REDACTED]",
  "AZURE_OPENAI_DEPLOYMENT": "nextcore-gpt-5-4-mini",
  "AZURE_OPENAI_API_VERSION": "2024-06-01",
  "AZURE_OPENAI_API_STYLE": "chat-completions"
}
```

PowerShell local dev server example:

```powershell
cd D:\NextCore\Projects\SPFx\NextCore-projects\function-app
$env:PORT=7072
$env:AI_PROVIDER="azure-openai"
$env:AZURE_OPENAI_ENDPOINT="https://YOUR-RESOURCE.services.ai.azure.com/openai/v1/responses"
$env:AZURE_OPENAI_API_KEY="[REDACTED]"
$env:AZURE_OPENAI_DEPLOYMENT="nextcore-gpt-5-4-mini"
$env:AZURE_OPENAI_API_VERSION="2024-06-01"
$env:AZURE_OPENAI_API_STYLE="responses"
npm run start:mock
```

`start:mock` is still the local Node dev server name, but when `AI_PROVIDER=azure-openai` it calls the real Azure OpenAI deployment.

## OpenAI local settings

If using OpenAI API directly instead of Azure OpenAI:

```powershell
cd D:\NextCore\Projects\SPFx\NextCore-projects\function-app
$env:PORT=7072
$env:AI_PROVIDER="openai"
$env:OPENAI_API_KEY="[REDACTED]"
$env:OPENAI_MODEL="gpt-4o-mini"
npm run start:mock
```

Note: a ChatGPT Plus/Pro subscription is not automatically the same as API access. The backend needs an API key or Azure OpenAI deployment credentials.

## What the model receives today

The current SPFx web part sends metadata/context, not full file content:

- question
- scenario/mode/contextType
- site/page/library/folder metadata
- selected file metadata
- lightweight snippets generated by the UI

This is enough to verify a real model call and response rendering. Full legal document grounding requires the next phase:

```text
Microsoft Graph file retrieval or Azure AI Search index
  -> chunk document content
  -> retrieve relevant chunks
  -> send grounded snippets to the model
  -> return source-linked citations
```
